# 任务切换与经验接续

用于本技能参与的任务结束后，用户在同一对话发起下一项独立工作。判断由已经处理当前请求的助手完成；runner 不读取聊天记录，不另调模型，不轮询对话。技能被自动选择或显式调用后才执行这些指引，不能承诺所有聊天都弹出提醒。

## 判断时机

先用当前可见上下文判断，缺少证据时不要把上一项标为完成，也不要扫描整份历史来寻找触发条件。

| 当前情况 | 行为 |
| --- | --- |
| 视频 A 已交付，用户提供视频 B 的新素材并要求剪辑 | 新任务，提醒一次 |
| 同一项目的成片已交付，用户开始另一集 | 仍是新任务，不以文件夹相同为由漏掉提醒 |
| 用户修改已交付视频的字幕、配音、时长或封面 | 原作品返修，直接继续 |
| 渲染报错、仍在等待、质量审核未过，或同一批次下一步 | 原任务未完成，继续处理 |
| 用户明确要求新开对话 | 已有新建授权，直接准备交接；不再问是否新开 |
| 用户明确说在这里继续，或已拒绝本次建议 | 尊重选择，继续当前对话，不重复询问 |

“完成”指整个用户任务已交付且适用检查通过，不是某个 runner 状态变为 succeeded。仅同类任务、只说“继续”或目标尚不明确，不足以认定新任务。

## 一次提醒，两项选择

在新任务的昂贵制作开始前，用已有验收记录或当前上下文备好简短交接内容，以及值得制作技能的具体流程范围，再提醒。不要先迁移后询问。

示例措辞（按实际情况和用户语言调整）：

> 上一个视频已完成，这次是新的剪辑。是否新开对话，并携带已验证的剪辑经验，减少旧上下文？这套剪辑和验收流程也可以整理成可复用技能，是否一起制作？

新开对话和制作技能是两个独立选择；允许只换对话、只做技能、两者都做、或继续原对话。有提问工具时合并在一次调用中，遵守宿主的提问方式。没有可复用流程时不要为了提问而虚构经验；直接提供简短交接选项。

每个独立新任务只提醒一次；用户说“这个对话别再提醒”就抑制本对话后续提醒。偏好不自动升级为全局设置。提醒不是工作审批门槛：等答复时可做必要的轻量只读准备；用户没有回答时按宿主规则给出合理答复时间，然后说明暂在当前对话继续，不擅自开新对话或制作技能。

## 精简交接

使用 [交接模板](../assets/task-handoff-template.md)，删除不适用项。优先复用已有简短项目记录；需要落盘时，在旧项目允许的 work 目录保存独立的 `handoff-<task-key>.md`，不覆盖无关文件。无文件能力则提供可复制文本。

- 正文尽量控制在 1,200 个字符以内；这是摘要长度目标，不是 token 估算。最多保留五条可迁移经验，大文件只给位置。
- 写清新任务目标、输入与输出位置、仍适用的用户偏好、已验证的工具/参数/脚本和验收方法，以及新任务仍需重验的条件。路径用实际绝对路径，不猜测新素材或输出目录。
- 每条“成功经验”附简短证据，如成片位置、测试结果或用户确认。把候选方法、失败尝试和未完成检查标为未验证，不混入已验证做法。
- 携带相关经验，不附整段对话、全部工具输出、日志、令牌、私密账号信息或一次性发布授权。新任务的费用、发布、删除等操作仍按其实际授权处理。
- 模板中的本次提醒状态只用于避免同一新任务被再次询问，不是长期记忆。不要读取或修改全局记忆、AGENTS.md、自动化或其他技能来实现监听。

用户同意新开后，使用当前宿主已有的新建对话工具，并遵守其项目/目录选择规则；只发送新目标、相关约束和摘要路径或正文。不要通过 fork 复制全部历史来宣称缩短上下文。工具不具备该能力时，给用户准备好的开场提示，不声称已创建。

可用的开场提示：

> 新任务：〔本次目标〕。使用 $long-task-runner；先读取〔实际交接文件绝对路径，或直接附精简摘要〕，核对输入、脚本和依赖仍可用，沿用适用的已验证经验，再执行本次任务。旧任务已结束，不重新加载旧对话；本任务尚未执行。〔本次用户已确认的技能制作选择〕。

新对话能否读到旧文件取决于宿主和项目权限；不同设备或不可访问的目录，改为携带精简正文，并明确缺失资源。看到以前的命令成功，也要重验新输入和时效性依赖。

## 制作可复用技能

只在用户同意后执行；已经明确要求制作时不再重复确认。使用当前可用的 skill-creator 或宿主同等机制；优先更新已有适用技能，避免每个作品生成一个近似技能。

只沉淀可复用的步骤、参数选择原则、现有脚本接口、质量标准和有证据的避坑方法。将素材、输出路径、账号和一次性偏好参数化。一个项目的成功经验不自动成为所有任务的强制规范，也不代表获得公开发布技能的授权。

若用户同时选择新对话和制作技能，把已验证经验及这项授权一并交接；由一侧制作一次即可。用户拒绝制作技能时，精简交接仍然可用；提醒不强迫用户先建技能才能开始新任务。

## 能力边界

减少旧上下文是建议目的，不承诺具体节省比例或免计费；实际 token、缓存和宿主自动记忆会影响结果。这个功能是技能指引及交接模板，没有新增后台进程、模型请求、聊天监听或线程 API 依赖。
