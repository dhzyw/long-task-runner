# 借鉴与可选压缩层（按需读取）

2026-09-08 核对上游说明，只借鉴机制，不继承宣传中的节省比例，也不复制代码或安装其完整运行时。

| 方向 | 本 skill 的落点 | 能力边界 |
|---|---|---|
| [HiveScanner](https://github.com/dhruvil009/hivescanner) 的本地轮询、状态增量和批量合并 | worker 本地等待；只在状态转换落事件；`status --since` 按任务合并变化，默认不返回连续日志 | 上游主要为 Claude Code；其宿主唤起方式不能直接套到本 Codex 工具。当前不存在已验证的任意 worker 自动唤醒接口 |
| [Turnlock](https://github.com/fanilosendrison/turnlock) 的代码流程和显式语义判断节点 | 顺序任务、退出条件、有限重试由代码执行。启动前、不可恢复错误、最终审核才交给模型；必要的中间判断将队列分段 | 不实现后台代理调用。上游交接协议也需要宿主读取、执行并重新启动程序；协议本身不保证宿主自动重启 |
| [RTK](https://github.com/rtk-ai/rtk) 的 CLI 输出精简 | 先用内置快照与有界日志；已安装且确实还有大量重复日志时，对落盘日志做一次本地过滤 | 先检查环境是否已安装；不自动安装或修改 hooks。不能让过滤器的成功退出覆盖原任务失败；保留关键错误、样本位置和原日志路径 |
| [Context Mode](https://github.com/mksglu/context-mode) 的原始输出隔离、索引和按需检索 | 环境已提供相应工具且需查大型报告时，将报告留在其数据区，按失败编号/任务 ID 只检索所需段落 | 仅在当前环境已经提供相应工具时使用，不自动安装 MCP/全局路由；它是可选数据读取层，不是任务完成通知能力 |

使用顺序：runner 状态/失败摘要 → 需要才读 `logs --bytes 4096` 或具体产物字段 → 仍过大才考虑已有压缩/检索工具。不要把普通短输出送进额外工具；工具说明、索引初始化和新增来回也有成本。不能把原始数据变短当作减少模型唤起的充分证据，两类开销分开测。

引入现有工具前先做一个廉价已知失败样本：确认原退出码不变，根因行、失败编号、产物位置可追溯；比较返回字节。RTK 的估算 token 或上游百分比不视为当前 Codex usage。产物验证使用原始事实或结构化报告，不能解析压缩后的宣传式成功摘要作为完成依据。
