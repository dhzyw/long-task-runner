# 同一个执行模式的场景

先选真实完成信号，再配置 argv 与检查；runner 的 succeeded 不代替专业质量审核。下表是适配指导，只有核心、短模拟任务和只读 HTTP 示例经过此包验收，没有声称实测每款软件。

| 场景 | 完成信号 | 异常信号 | 适配方法/保留的审核 |
|---|---|---|---|
| 视频生成/渲染 | 渲染退出 0，编码可解码，时长/音画轨/尺寸匹配 | 非零退出、损坏帧、缺音轨、时长偏差；慢帧本身不算失败 | 复用已有渲染脚本；GPU 锁；ffprobe 断言+按风险解码检查；抽查画面、字幕、音画同步。云生成用已知作业 ID 跟踪 |
| Blender 等 3D 渲染 | CLI 结束+预期帧范围/数量+图像可解码 | 缺帧、OOM、设备错误、损坏输出 | 后台前台化命令（Blender 的后台渲染进程仍应等渲染结束）；帧清单校验；检查材质、光照和构图 |
| 3D 烘焙/模拟 | 应用完成状态+指定缓存帧/贴图通道完整 | 未保存缓存、提前退出、无效数值 | 应用脚本写带 expected/completed/valid 字段的报告；runner 验 JSON；大缓存需独立校验任务。只在软件支持且确认后使用检查点 |
| 本地 TTS | 音频完整可读、时长区间/句子数量合理 | 空/截断音频、过长静音、文本遗漏 | 复用 TTS CLI/API 本地脚本，串行占 GPU；wav 或 ffprobe；按需静音检测，听审发音和情绪 |
| 批量 ASR/字幕 | 全部输入有对应结果、字幕可解析、时序单调且时长合理 | 漏文件、空文本、越界时间、任务非零退出 | 一个队列任务处理一个有意义批次；业务验证器输出 JSON；抽样核对听写，不按“有 SRT”通过 |
| OCR/文档转换 | 页数/文件数相符，目标格式可打开 | 缺页、损坏、OCR 结果异常空白 | CLI+页清单/解析校验；抽查排版、表格、关键文字 |
| 音视频转码/压缩 | 编码退出 0+解码+码流参数/时长符合 | 断流、损坏、丢音轨、大小越界 | ffmpeg argv，用输出临时文件避免覆盖原件；验证后按已授权范围替换 |
| 模型/大文件下载 | 下载进程成功+官方散列/尺寸清单一致 | 校验不符、认证失效、无磁盘空间 | 支持续传的既有下载器；仅对幂等下载重试；不把半成品重命名为完成文件 |
| 依赖安装 | 安装器退出+目标环境导入/版本验证 | 冲突、提示交互、重启/退出码约定 | 固定环境/锁文件，显式非交互；安装可能非幂等，默认不重试。先理解 MSI 等工具的非零成功码，审核包装器 |
| 编译/长测试 | 构建产物或测试报告+真实退出结果 | 编译失败、失败用例、报告未生成 | 输出日志限额，测试/构建可顺序排队；验证实际版本/目标，而非只看摘要文本 |
| 训练/微调/评测 | 预期 step/epoch 完成+可加载检查点+有限数值指标 | OOM、NaN、未完成 epoch、损坏检查点 | GPU 锁/线程/batch 由应用控制；只有配置明确且重复写入安全才恢复；本地运行不等于质量合格；付费远程训练不重提 |
| 数据清洗/ETL | 行数/模式/约束/事务提交状态满足 | 丢行、重复主键、异常空值、部分提交 | 幂等 staging 与原子发布；数据库写入若可能重复提交按 external 禁止重放 |
| 向量索引 | 文档计数/版本一致+检索烟测成功 | 漏文档、向量维度错误、索引打不开 | 本地 embedding/索引批次；云 embedding 有费用，不把失败批次全量重计费；使用已确认缓存/请求 ID |
| 科学计算/仿真 | 求解器终止条件、收敛/误差/守恒验证 | 非收敛、NaN、结果越界、资源耗尽 | 退出码+领域断言报告；长验证单列任务；无日志不算卡死 |
| 备份/同步 | 清单/散列或还原抽检通过 | 漏文件、权限/容量错误、部分传输 | 默认可恢复拷贝，单向范围明确；镜像删除须原授权，不能因通用 skill 自动扩大删除范围 |
| 远程异步作业 | 查询已持久化 ID 达到明确终态+输出可取得/验证 | 失败终态、ID 不匹配、未知状态、读取失败超限 | 现成状态查询 CLI 或 `remote_watch.py`；只查询、不提交；本地取消不停止远程收费 |

少量示例，按项目实际格式调整：

- 视频：主任务跑已有 `render.py`，checks 先检查新输出，再用 `scripts/check_media.py <文件> --min-duration 10 --max-duration 12 --require-audio --require-video --width 1920 --height 1080 --decode`（数值按项目替换）。它断言时长/音画轨/尺寸，`--decode` 额外完整解码；`ffprobe` 自身退出 0 不证明参数符合要求。依赖已有 ffprobe/ffmpeg，不自动安装。超过 300 秒的解码列作独立任务并设置对应 `--decode-timeout`，不缩短后冒充全片验证。
- Blender：主 argv 可为 `blender.exe -b scene.blend -o <输出帧前缀> -s 1 -e 120 -a`。验证器应列出 1–120 每帧并解码/核对尺寸；仅目录存在或已有部分帧不足。修改建模代码、效果决策继续由模型/用户审核，runner 只接耗时执行段。
- 本地 TTS：原脚本输出 WAV 时用 `{"kind":"wav","path":"voice.wav","min_duration_s":20,"max_duration_s":35}`；合理区间来自稿件/项目，不能套用示例常数。PCM 结构通过后仍需检查静音和试听。
- 远程：把 `python remote_watch.py --url ... --job-id ... --output remote-result.json` 放入一个 read_only task，配置 JSON `equals` 匹配该供应商的成功状态，再单列下载和产物验证。若状态结构嵌套或非 HTTP，写一个薄查询脚本继续复用同一 runner，不建插件框架。
